# Жизненный цикл разработки ПО (SDLC)

**Жизненный цикл (ЖЦ)** — путь, который проходит продукт: от момента задумки до вывода из эксплуатации.

---

## Этапы ЖЦ ПО

### 1. Планирование и анализ требований

Включает в себя:

- Описание задач, которые должен решать продукт
- Опрос стейкхолдеров
- Выявление аудитории, которая будет пользоваться решением
- Оценка ресурсов, которые нужны для реализации
- Согласование критериев

### 2. Определение требований

- Оценка рисков
- Выбор методов работы
- Описание пользовательских сценариев

### 3. Проектирование

#### Верхнеуровневое проектирование

- Основные компоненты системы: модули, сервисы, подсистемы
- Принцип взаимодействия этих компонентов между собой
- Общая архитектура системы: клиент-сервер, архитектура или микросервисы
- Зависимость решения от других систем
- Протокол интерфейса

#### Низкоуровневое проектирование

- Принцип работы отдельных компонентов системы
- Алгоритмы, структуры данных и логика работы внутри каждого модуля
- Детали реализации: какие классы, методы или функции будут созданы
- Взаимодействие с БД, API или другими внешними системами

### 4. Разработка

Непосредственное написание кода и создание продукта.

### 5. Развертывание

Внедрение продукта в рабочую среду.

### 6. Поддержка и сопровождение

Когда компьютеры устанавливаются в технику, поддержка айтишников не останавливается: исправляются ошибки, выпускаются обновления.

### 7. Смерть ПО (Вывод из эксплуатации)

Продукт перестает поддерживаться и использоваться.

---

## Модели ЖЦ ПО

### Каскадная (Waterfall)

- Последовательное выполнение этапов
- Переход только вперёд, возврат затруднён
- Полное документирование до старта

### V-образная

- Упор на тестирование
- Каждому этапу — этап проверки
- Верификация и валидация

### Итеративная

- Разработка итерациями
- В каждой итерации — все этапы
- Постепенное наращивание функциональности

### Инкрементная

- Продукт по частям (инкрементам)
- Каждая часть — новая функциональность
- Возможность выпуска частями

### Спиральная

- Сочетание итеративности и анализа рисков
- Каждый виток — новая версия
- Постоянная оценка рисков

### Agile

- Гибкая разработка
- Короткие итерации (спринты)
- Постоянное взаимодействие с заказчиком
- Быстрая реакция на изменения

### Scrum (фреймворк Agile)

- Спринты 2–4 недели
- В конце каждого — рабочий продукт
- Ретроспектива

### Kanban (метод управления потоком)

- Визуализация задач на досках
- WIP-лимиты
- Не замена модели, а улучшение процесса

---

## Как выбрать модель

- Можно сочетать несколько подходов
- **Agile Suitability Filter** — опросник для выбора: предиктивный, гибкий или гибридный подход

## Управление этапами (инструменты)

**Kaiten** — таск-трекер для любой модели:

- Канбан-доски для визуализации
- Шаблонные чек-листы
- Декомпозиция задач
- Спринты по Scrum
- Хранение документации
- Отчёты: Диаграмма Ганта, Накопительная диаграмма потока
